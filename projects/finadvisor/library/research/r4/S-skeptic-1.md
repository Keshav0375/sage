## Hidden assumptions (a decision would rely on these without a source)
1. The Handbook corpus path. A-eu-uk assumes website OGL gives automated ingestion; T&C cl.35.3 says no. Only the API (revocable, delete duty, current version only) or written consent. Point-in-time history for the Handbook therefore cannot be built from the API, and cannot be crawled from the site.
2. The FINRA substitute. "Use SEC-hosted rule-filing text" assumes the SEC page's "may be copied" licenses FINRA-authored text. The SEC page does not address third-party copyright. The file marks it inference; any ADR must keep it as a legal question.
3. Fund-company KIDs/497K/ADV brochures. The demo corpus (3 fund families, 10-20 brochures, KIDs) assumes reuse is tolerable. No open licence was found for any of them. "Public" is not "licensed", especially for a multi-tenant product that stores and quotes them.
4. ESMA reuse conditions (disclaimer on transformed text, "free from ESMA" notice if sold) apply to a RAG product that summarises: the product must emit the disclaimer. Not in any design.
5. Model Armor as a gate: quota is per project and shared by prompt, ingest and output checks; 1200 QPM and the 2M free tokens are not modelled against corpus size. The 500 ms fail-closed timeout has no vendor figure (the file says this).
6. Prompt Guard 2 recall (97.5%) is quoted as if general; it is Meta's private benchmark, English, 512-token windows. A 100 KB 497K is about 25k tokens, so about 50 windows per document at ingest.
7. Spotlighting is cited as evidence for an Anthropic model; it was never tested on Claude (file says so) and uses a trivial keyword attack.
8. Golden-set sizing assumes independent items; items drawn from the same document are clustered, so the real interval is wider (file notes it). Labelling-hour budget (32-78 h) is the file's own estimate with no source.
9. Anthropic: "no EU residency" is true for the first-party API; the alternative (Claude on Vertex EU endpoint) is unverified, as are Voyage regions and Identity Platform data location. A UK/EU residency promise currently has no verified LLM path.
10. Identity Platform same-email-in-two-tenants behaviour is unread and untested; the multi-login design depends on it.
11. The rate limits are all "documented ceilings"; none of the US/EU/UK ingest paths measured real throughput. eCFR limits unverified; CELLAR limits undocumented.

## Most dangerous problem
The UK corpus plan (crawl the FCA Handbook website under OGL) violates the Handbook site's own terms (cl.35.3 bans automated access except via the API), and the permitted API route is revocable with a delete duty and has no history, so point-in-time UK answers cannot be built lawfully without written FCA consent.
