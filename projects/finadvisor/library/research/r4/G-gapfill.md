## 1. PostgreSQL 18 temporal constraints
- PK/UNIQUE syntax — "UNIQUE [ NULLS [ NOT ] DISTINCT ] ( column_name [, ... ] [, column_name WITHOUT OVERLAPS ] )" / "PRIMARY KEY ( column_name [, ... ] [, column_name WITHOUT OVERLAPS ] )" — https://www.postgresql.org/docs/18/sql-createtable.html (PG 18 current, page footer 18.6; read 2026-11-02)
- Semantics — "If the WITHOUT OVERLAPS option is specified for the last column, then that column is checked for overlaps instead of equality... So for example UNIQUE (id, valid_at WITHOUT OVERLAPS) behaves like EXCLUDE USING GIST (id WITH =, valid_at WITH &&). The WITHOUT OVERLAPS column must have a range or multirange type. Empty ranges/multiranges are not permitted." — same URL
- btree_gist — "The non-WITHOUT OVERLAPS columns ... can be any type that can be compared for equality in a GiST index. By default, only range types are supported, but you can use other types by adding the btree_gist extension (which is the expected way to use this feature)." — same URL. (So btree_gist needed for e.g. integer/uuid/text key columns.)
- Index — "if the constraint includes a WITHOUT OVERLAPS clause, it will use a GiST index." — same URL
- FK syntax — "FOREIGN KEY ( column_name [, ... ] [, PERIOD column_name ] ) REFERENCES reftable [ ( refcolumn [, ... ] [, PERIOD refcolumn ] ) ] [ MATCH matchtype ] [ ON DELETE referential_action ] [ ON UPDATE referential_action ]"
- FK semantics — "the constraint is considered satisfied if the referenced table has matching records (based on the non-PERIOD parts of the key) whose combined PERIOD values completely cover the referencing record's... the referenced table must have a primary key or unique constraint declared with WITHOUT OVERLAPS." At least one non-PERIOD column required.
- Limits — for RESTRICT, CASCADE, SET NULL, SET DEFAULT: "In a temporal foreign key, this option is not supported." NO ACTION not marked unsupported (inference; page silent).
- Note: /docs/18/ddl-constraints.html did NOT mention WITHOUT OVERLAPS in the fetch (reader summary) — treat CREATE TABLE ref as the source.

## 1b. pgvector iterative scans
- Latest on README: v0.8.7 (README install commands/Docker tags); read 2026-11-02 https://github.com/pgvector/pgvector (README)
- Problem — "With approximate indexes, queries with filtering can return less results since filtering is applied after the index is scanned."
- Feature — "Starting with 0.8.0, you can enable iterative index scans ... which will automatically scan more of the index until enough results are found (or it reaches hnsw.max_scan_tuples or ivfflat.max_probes)."
- Modes — hnsw.iterative_scan = strict_order | relaxed_order; ivfflat.iterative_scan = relaxed_order. "Strict ensures results are in the exact order by distance"; "Relaxed allows results to be slightly out of order by distance, but provides better recall".
- Settings — hnsw.max_scan_tuples default 20,000 (approximate; does not affect initial scan); hnsw.scan_mem_multiplier default 1 (x work_mem); ivfflat has NO max_scan_tuples: it is ivfflat.max_probes ("If this is lower than ivfflat.probes, ivfflat.probes will be used").
- Guarantee: NO guarantee of LIMIT-many results or full recall; stops at limits. Strict gives exact ordering of returned rows only. (reader summary; README silent on hard guarantee)

### 2609.35815 evalstats (v1, 2026-09-20; Arawjo)
- Claims: raw LLM-judge scores inflate false positives; for numeric IRR metrics "false positive risk peaks at high IRR"; rule of thumb human-LLM alignment rho^2 >= 0.4 to be worthwhile, below 0.2 judge too poor. Nine PPI-corrected tests; Type I error calibrated in sweep (2,046 null scenarios/test, 200 MC replicates each, ~3.68M trials). Recommendations for N<100: CIs — Jeffreys/Wilson for single binary, logit-t for continuous, Bonett-Price for paired binary, Bayesian NIG for Likert; "bootstrap CI methods were overconfident nearly everywhere"; Romano-Wolf step-down for FWER "only at n>=30". Case study: judge at median quadratic kappa 0.63 ("substantial") -> naive spurious finding; with evalstats PPI Kruskal-Wallis rejects null 5.0% (15/300), combined false-positive 3.7% (same as 30 human-only items).
- Caveat: simulation-based, single author, preprint.
